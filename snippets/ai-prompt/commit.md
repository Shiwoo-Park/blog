# 코드 커밋 요청

## 작업 절차

1. `git status` → 변경사항 확인
2. `git diff` → 변경 내용 분석
3. 버그 발생 가능성이 있는 부분 검토: 있다면 커밋을 멈추고 해당 부분에 대해 리포트, 없다면 다음 단계
4. 커밋 메시지 생성 (Conventional Commits 형식)
5. `git add` → `git commit`

## 커밋 메시지 규칙

- 형식: `<type>(<scope>): <subject>` + 2-4개 bullet point
- Type: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`
- 원칙: 간결하게, 무엇을 변경했는지(What)에 집중
- 금지: 테스트 통과 여부, 파일 경로, 구현 세부사항, 마이그레이션 언급
- 코드 수정의 목적이 다양할경우 아래 주제로 분류하여 리스트업할 것
  - 기능추가, 리팩토링, 기타
- 커밋메시지의 맨 마지막에 `기존 서비스 영향범위` 항목을 추가
  - 변경사항을 테스트 할때 참고 가능하도록 간단하게 기록
    - ex1. CancelOrderService.normalize_cancel_data() 내부 validation 추가
    - ex2. GET /v2/home 응답 포맷 변경 (데이터 추가)
  - 중요도를 상,중,하 로 나누어서 높은것부터 나열

## 커밋 메시지 예시

```text
feat: 기능1

- 내용1
  - 세부내용1-1
  - 세부내용1-2
- 내용2
  - 세부내용2-1

[기존서비스 영향범위]
- (상) 내용1
- (중) 내용2
- (하) 내용3
```
