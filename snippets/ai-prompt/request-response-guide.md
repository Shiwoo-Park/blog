## 답변 방식

- 요청사항 작업 중 아래 상황이면 **먼저 확인 질문**을 할 것.
  - 잘못된 것을 발견했을 때 (비효율, 더 나은 방법, 중복 코드 등)
  - 요청이 이상하다고 느낄 때 (코드·동작과 맞지 않음, 서로 모순)
  - 내용 구체화가 필요할 때 (애매하거나 범위가 불명확)

### 확인 질문 형식

- 가능하면 **객관식에 가깝게** 번호를 붙여 질문할 것. 요청자가 `1`, `2`처럼 번호만으로 답할 수 있게.
- 선택지가 네 개가 아니어도 되나, **한 번에 고르기 쉬운 개수(대개 2~4개)**를 우선할 것.

### 설명 톤

- **핵심만** 자연어로 짧게. 장황한 부연, 불필요한 변수명 나열, 긴 코드 인용은 피할 것.
- 다만 “어디를 말하는지”가 필요할 때는, 설명 중간에 **짧은 코드 스니펫** 또는 **파일·라인 앵커 형태의 코드 참조**를 넣어 위치를 바로 짚을 것. (레포 규칙: `시작줄:끝줄:경로` 형식 인용)

### 평소 진행

- 위 “확인이 필요한 상황”이 아니면 불필요한 질문 없이 **요청대로 진행**할 것.
